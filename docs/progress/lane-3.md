## Decisions
- 2026-10-03 Items 1 and 2 share migration 185 (`priority`, `special_offer_text`, `external_refs`, `page_settings`, `cms`) and land as one commit per repo.
- 2026-10-03 `page_settings` keeps the spec's snake_case keys; only changed keys are stored, defaults resolved in `catalog/productPage.js` (inline form, sticky button and reviews default on = the page's behaviour before the settings).
- 2026-10-03 `free_shipping` is not a page setting: the existing `shippingMode: 'free'` already does it.
- 2026-10-03 Countdown: `page_settings.countdown.ends_at`. After it passes, `effectiveVariantPrice` sells the variant at its compare-at price (storefront, cart and order pricing use the same function). Fixed-price offers (bundles) are not changed by it.
- 2026-10-03 The theme's `productCountdownHours` (restarts for every visitor) is no longer shown on the product page: SPEC §21 forbids fake counters; only the real countdown shows.
- 2026-10-03 Option display types are stored in `Product.options[]` (`displayType`, `swatches`, `images`); option names/values still come from the variants.
- 2026-10-03 `landing_page_id` is stored and validated as a uuid only; rendering a builder page in place of the product template belongs to lane 5's builder.
- 2026-10-03 Hidden products are left out of listings, search and suggestions; priority sorts first in the `newest` and `position` sorts (the id-cursor listing keeps its order).
- 2026-10-03 Bulk shipping change offers only standard/free (extra_fee needs an amount per product). Bulk price applies to every active variant: set, +% or −%.
- 2026-10-03 A duplicate copies active variants without SKU or stock (SKU is unique per store), active offers and collection membership; it is always a draft.
- 2026-10-03 Stock typed in the variant table is saved as an inventory adjustment movement, never written directly.
- 2026-10-03 Manual reviews: `reviews.customer_id` nullable + `author_name`, `photos`, `source` (migration 186). Approved by default; only manual ones can be deleted. Shopper reviews show first name + initial.
- 2026-10-03 Shopper review form has no photo upload: customer uploads are private, short-lived files; photos come with manual reviews. Shopify review import is left to item 5's import work.
- 2026-10-03 Import: every source becomes the same "transfer product" list stored on `catalog_imports` (migration 187); the `io` job `catalog.import` (catalog/jobs.js) creates products through catalogService and writes the per-row report. JSON money is minor units; the sheet is major units.
- 2026-10-03 No spreadsheet dependency: `importExport/sheetReader.js` reads CSV and .xlsx (zip + XML) itself; the template is CSV with a BOM (opens in Excel).
- 2026-10-03 Shopify link: https only, public addresses only (webhookUrlGuard lookup), no redirects, 2 MB cap; images stay as the source URLs; SKUs dropped; always a draft. Other link sources (AliExpress, Amazon…) are the spec's open decision — not built. Shopify review import not built.
- 2026-10-03 The api-client's private `rawFetch` is reached by one typed cast in endpoints/catalog.ts for the multipart upload (client.ts may not be edited).
- 2026-10-03 Header collections ride on the public store (`headerCollections`, at most 12) and join the header menu after the pages lane 5 put there. A hidden collection is never in the header. Search facets still count hidden collections.
- 2026-10-03 Bundles: tables `bundles` + `bundle_tiers`, `products.bundle_id` (migration 189). One function (`bundles/bundlePricing.priceUnits`) prices units against tiers; it is applied to order lines, the shipping quote and cart totals, and prices every tier per variant on the public product. Percentage is stored ×100 (500 = 5%). More units than the largest tier are taken tier by tier, largest first.
- 2026-10-03 A bundle covers plain variant lines only (no offer, no bump). Its saving lowers the line totals (`line_discount_amount`) and is recorded in `discountsSnapshot` as `{kind:'bundle'}`, apart from the coupon entry; `order.discountAmount` stays the coupon only.
- 2026-10-03 A variant per unit on Buy Now: checkout takes `extraItems` beside `item`. Bundles use the products.view / products.manage permissions.
- 2026-10-03 Dashboard: a new "Offers" nav entry (/offers, a hub of cards that item 11 extends) and /offers/bundles. Storefront: components/product/BundlePicker.tsx; the first piece follows the page's option pickers, the others have a variant select each; a product with custom fields keeps the plain add-to-cart button (one line).
- 2026-10-03 Item 8 rules live in modules/offers (migration 190: order_bumps, cross_sell_rules, upsell_rules, upsell_acceptances). A product bump and an upsell sell an existing Offer (the spec's priceAmount/discountPercent on a bare variant is not built: the offer's price is the bump's price), like the existing store-wide bump, which stays.
- 2026-10-03 Cross-sell rules carry no discount (spec's discountType/discountValue not built); with no matching rule the suggestion is what real orders show was bought together.
- 2026-10-03 Store upsell: thank-you page only, COD orders that nobody has opened, within 30 minutes, once per order (unique index), proven by order id + order number. Exit downsell config is settings.exit_downsell via its own GET/PUT; the popup is not served when its coupon is no longer usable.
- 2026-10-03 Storefront offer pieces live in components/offers/StoreOffers.tsx; product bumps are on the product page's inline form (the cart checkout keeps the store-wide bump only); cross-sell is on the cart page (placement cart); the exit popup remembers "seen" in localStorage per store.
- 2026-10-03 Item 9 lives in discounts/couponExtras.js: POST /discounts/bulk (≤500 random codes, one use each by default, no look-alike characters); a discount with no code is applied by itself when no code was typed (the one taking the most off; percentage and fixed only); POST /store/:ws/coupon-preview; settings.min_order_amount via GET/PUT /offers/order-rules, enforced for shoppers only (not staff orders, not funnel add-on orders). The shipping quote carries automaticDiscount and minimumOrder.
- 2026-10-03 "Once per customer by phone or email" is not built: perCustomerLimit already counts by customer, and a customer is found by phone. The global coupon switch is the existing allow_discount_codes.
- 2026-10-03 Storefront coupon pieces live in components/offers/CouponBits.tsx: the link's code is kept in localStorage per store; the product form sends it only when the preview says it applies; the cart checkout prefills the code box with it. useShippingQuote now also returns `extras` (automatic discount, minimum order, bundle saving).
